# Персональные данные и законы РФ: что сделано и что осталось сделать вам

> **Важно.** Документы в этом проекте подготовлены как **шаблоны** на основе того, какие данные сайт реально собирает, и требований 152-ФЗ «О персональных данных». Это не юридическое заключение. Перед запуском сайта дайте тексты на проверку юристу: закон и практика Роскомнадзора меняются, а ответственность оператора серьёзная (штрафы по ст. 13.11 КоАП РФ).

## Какие данные собирает сайт

| Данные | Откуда | Куда попадают | Сколько хранятся |
|---|---|---|---|
| Имя (необязательно) | форма «Заказать звонок» | файл `leads.jsonl` на сервере и сообщение в Telegram-чат | 365 дней, потом автоудаление с сервера |
| Телефон | форма | там же | там же |
| Комментарий | форма | там же | там же |
| Дата и время заявки, версия документа «Согласие» | сервер при отправке | `leads.jsonl` | там же |
| IP-адрес | при обращении к сайту | оперативная память (лимит заявок) и журналы Docker (3 файла по 10 МБ, затем перезаписываются) | пока журнал не перезапишется |

Cookie и аналитики на сайте **нет**. В браузере хранится только выбранная тема (светлая или тёмная), это не персональные данные.

## Что уже сделано в проекте

| Требование | Что сделано |
|---|---|
| Опубликованная политика обработки ПД (ст. 18.1 152-ФЗ) | Страница `/privacy/`, ссылка в подвале и у галочки в форме. Исходник: `frontend/legal/privacy-policy.md` |
| Согласие на обработку отдельным документом (ст. 9, с 01.09.2025) | Страница `/consent/`, ссылка у галочки. Исходник: `frontend/legal/consent.md` |
| Согласие не предустановлено, без него заявка не принимается | Галочка пустая по умолчанию; форма и сервер (`consent_required`) не принимают заявку без согласия |
| Подтверждение, что согласие было дано | В каждую заявку сохраняется дата, время и версия документа «Согласие» (`consentVersion`) |
| Срок хранения и удаление | `LEADS_RETENTION_DAYS` (по умолчанию 365), сервер раз в сутки удаляет старые заявки; срок указан в политике |
| Ограничение объёма данных | Собираются только имя, телефон, комментарий; специальные категории не запрашиваются |
| Защита | HTTPS, ограничение числа заявок с одного IP, API недоступен снаружи, порты закрыты firewall |
| Реквизиты оператора на сайте | Строка в подвале появляется автоматически, когда вы заполните `frontend/legal/operator.json` |

## Что нужно сделать вам (по порядку)

1. **Заполнить данные оператора** в `frontend/legal/operator.json`: ФИО ИП или название организации, ИНН, ОГРНИП/ОГРН, адрес, e-mail для обращений, ответственный, где стоит сервер. Пока там остаются `[квадратные скобки]`:
   - на страницах документов показывается красное предупреждение «Это шаблон»;
   - страницы закрыты от поисковиков;
   - при сборке в консоли выводится предупреждение.
2. **Показать тексты юристу** (`frontend/legal/*.md`, этот файл и `internal-documents.md`).
3. **Сервер должен физически находиться в России** (ст. 18 ч. 5 152-ФЗ: первичный сбор и хранение данных граждан РФ в российских базах). Выбирайте VPS у российского провайдера и впишите в `operator.json` поле `hosting`. Зарубежный VPS (то, где часто дешевле) не подходит.
4. **Подать уведомление в Роскомнадзор** об обработке персональных данных (ст. 22 152-ФЗ) до начала обработки. Есть исключения, но в вашем случае они применимы не бесспорно (заявки собираются до заключения договора), поэтому безопаснее подать. Подаётся бесплатно на портале персональных данных Роскомнадзора ([pd.rkn.gov.ru](https://pd.rkn.gov.ru)), раздел с подачей уведомления; шпаргалка с готовыми формулировками в `internal-documents.md`, раздел 4.
5. **Внутренние документы** (приказ об ответственном, список лиц с доступом, журнал обращений): шаблоны в `internal-documents.md`. Их не нужно публиковать, но при проверке их просят предъявить. Если вы работаете один и без сотрудников, часть пунктов упрощается: смотрите примечания в файле.
6. **Решить вопрос с Telegram** (см. ниже).
7. После заполнения пересоберите и перезапустите сайт: `docker compose up -d --build`. Откройте `/privacy/` и `/consent/` и прочитайте тексты глазами владельца: всё ли правда про ваш бизнес.

## Telegram: риск

Заявки пересылаются в рабочий чат Telegram. С этим связаны два вопроса:

1. **Трансграничная передача.** Серверы Telegram находятся за рубежом, поэтому по ст. 12 152-ФЗ до начала такой передачи оператор обязан уведомить РКН о ней (отдельное уведомление, образец формулировок в `internal-documents.md`). В политике и согласии пересылка через Telegram и возможное хранение за рубежом указаны открыто.
2. **Доступность.** По сообщениям СМИ, с февраля 2026 года Роскомнадзор замедляет и ограничивает Telegram в России; актуальное положение дел проверьте сами: на момент подготовки документов проверить его не удалось. Если Telegram недоступен, бот не сможет доставить заявку. **Заявка при этом всё равно сохраняется** на сервере (`leads.jsonl`), её можно посмотреть командой `docker compose exec api cat /data/leads.jsonl`, но вы можете не узнать о ней сразу. Рекомендуется добавить запасной канал уведомления: e-mail или российский мессенджер (например, MAX). Это отдельная доработка бэкенда, скажите, и её можно сделать.

Если когда-нибудь откажетесь от Telegram, нужно будет обновить политику (п. 5.3) и согласие (п. 3).

## Как менять документы

- Тексты: `frontend/legal/privacy-policy.md` и `frontend/legal/consent.md`. Подстановки вида `{{operatorName}}` берутся из `operator.json`.
- **Изменили смысл документа** (новые данные, новые цели, новый получатель): обновите `documentDate` и `documentVersion` в `operator.json`. Новая версия будет записываться в заявки, и по ней видно, с какой редакцией согласился человек.
- **Изменили срок хранения:** поменяйте `retentionDays` в `operator.json` **и** `LEADS_RETENTION_DAYS` в `.env`, значения должны совпадать (политика говорит одно, сервер должен делать то же).
- Добавляете аналитику, cookie, рассылки, новые поля в форму: сначала меняйте документы, потом код.

## Обращения посетителей

Человек может написать на ваш e-mail с просьбой показать, исправить или удалить его данные или отозвать согласие. Срок ответа по закону: 10 рабочих дней (может быть продлён на 5). Как найти и удалить данные по номеру телефона:

```bash
# найти заявку
docker compose exec api grep "9001234567" /data/leads.jsonl
```

Для удаления заявки отредактируйте файл (остановите контейнер, чтобы он не записывал новую заявку одновременно):

```bash
docker compose stop api
docker compose run --rm --entrypoint sh api -c "grep -v '9001234567' /data/leads.jsonl > /data/leads.tmp && mv /data/leads.tmp /data/leads.jsonl"
docker compose start api
```

Удалите также сообщение в Telegram-чате и запишите обращение в журнал (форма в `internal-documents.md`).
