# Внутренние документы оператора (шаблоны)

Эти документы **не публикуются** на сайте. Они нужны, чтобы при проверке (или запросе Роскомнадзора) вы могли показать, что обработка данных организована. Заполните данные в `[скобках]`, распечатайте или храните в электронном виде, покажите юристу.

> Если вы ИП и работаете один, без сотрудников: ответственным назначаете себя, а «список лиц с доступом» состоит из вас. Часть формальностей для вас упрощается, но сами документы всё равно полезно иметь.

## 1. Приказ о назначении ответственного за организацию обработки персональных данных

```
ПРИКАЗ № [номер]
о назначении ответственного за организацию обработки персональных данных

г. Хабаровск                                                    [дата]

В соответствии со ст. 22.1 Федерального закона от 27.07.2006 № 152-ФЗ «О персональных данных»

ПРИКАЗЫВАЮ:
1. Назначить ответственным за организацию обработки персональных данных [должность, ФИО].
2. Ответственному:
   - осуществлять внутренний контроль за соблюдением законодательства о персональных данных;
   - доводить до сведения работников положения законодательства и локальных актов о персональных данных;
   - организовывать приём и обработку обращений субъектов персональных данных и контролировать сроки ответов.
3. Контроль за исполнением приказа оставляю за собой.

[Должность]  _______________ / [ФИО]
```

## 2. Перечень лиц, имеющих доступ к заявкам

| № | ФИО | Должность | Какой доступ | Дата допуска |
|---|---|---|---|---|
| 1 | [ФИО] | [руководитель / диспетчер] | Рабочий Telegram-чат, сервер (файл заявок) | [дата] |
| 2 | [ФИО] | [диспетчер] | Рабочий Telegram-чат | [дата] |

Правила для всех из списка (дайте им прочитать и подписать):

- заявки используются только для звонка клиенту и согласования выезда;
- нельзя пересылать заявки, скриншоты чата и номера телефонов посторонним, в личные чаты и соцсети;
- рабочий чат закрытый, в него добавляются только лица из списка, при увольнении человека его сразу удаляют из чата;
- доступ к серверу (SSH) только у [ФИО], вход по ключу, пароль не передаётся;
- заявки старше срока хранения (365 дней) удаляются из чата вручную раз в [месяц].

| № | Дата получения | Кто обратился (телефон, e-mail) | Суть (доступ / уточнение / удаление / отзыв согласия) | Что сделано | Дата ответа |
|---|---|---|---|---|---|
| 1 | | | | | |

Сроки: ответ в течение **10 рабочих дней** с получения (можно продлить не более чем на 5 рабочих дней, направив мотивированное уведомление). Данные по отозванному согласию удаляются в срок до 10 рабочих дней (если закон не требует хранить дольше).

Как найти и удалить заявку: `docs/legal/README.md`, раздел «Обращения посетителей».

## 4. Уведомление Роскомнадзора: шпаргалка

Подаётся один раз до начала обработки на портале персональных данных ([pd.rkn.gov.ru](https://pd.rkn.gov.ru)), при изменении сведений нужно подать информационное письмо об изменениях (в срок, который указан на портале). Ниже готовые формулировки по полям. Названия полей на портале могут меняться: ориентируйтесь на смысл.

| Поле | Что писать |
|---|---|
| Наименование оператора | как в ЕГРИП/ЕГРЮЛ ([ФИО ИП] или название организации) |
| ИНН, ОГРНИП/ОГРН, адрес | ваши реквизиты (те же, что в `operator.json`) |
| Ответственный за организацию обработки | [ФИО], телефон, e-mail |
| Цель обработки | Связь с заказчиками по заявкам на оказание услуг по откачке (обратный звонок, согласование времени и стоимости выезда), оказание услуги |
| Категории субъектов | Физические лица: посетители сайта, потенциальные и действующие заказчики услуг |
| Категории персональных данных | Имя, номер телефона, сведения, указанные в комментарии к заявке (общие категории) |
| Специальные и биометрические категории | Не обрабатываются |
| Правовое основание | Согласие субъекта персональных данных (п. 1 ч. 1 ст. 6 152-ФЗ) |
| Действия с данными | Сбор, запись, систематизация, накопление, хранение, уточнение, использование, передача (внутри организации), удаление, уничтожение |
| Способ обработки | Смешанная: с использованием средств автоматизации и без них; передача по сети интернет |
| Срок обработки | 365 дней с даты получения заявки или до отзыва согласия |
| Меры безопасности | Шифрование соединения (HTTPS), разграничение доступа, ограничение частоты запросов, регулярное обновление ПО сервера, автоматическое удаление данных по истечении срока, приказ об ответственном, перечень лиц с доступом |

| Передача третьим лицам | Хостинг-провайдер предоставляет только вычислительные мощности и к содержимому доступа не имеет (проверьте, не нужно ли указать его как обработчика) |

### Уведомление о трансграничной передаче (ст. 12 ч. 3)

Если пересылаете заявки через Telegram, подаётся отдельно (на том же портале) **до начала** трансграничной передачи. Нужны: сведения о принимаемых мерах защиты, правовое основание (согласие), категории данных и цели (как выше), перечень стран и получателей. Роскомнадзор вправе запретить или ограничить передачу в течение 10 рабочих дней. Это одна из причин рассмотреть замену Telegram на российский канал уведомлений (см. `README.md` в этой папке).

- [ ] `frontend/legal/operator.json` заполнен, на `/privacy/` и `/consent/` нет красного предупреждения
- [ ] Юрист прочитал `privacy-policy.md` и `consent.md`
- [ ] Сервер физически в России, поле `hosting` заполнено
- [ ] Уведомление в Роскомнадзор подано (и о трансграничной передаче, если используете Telegram)
- [ ] Приказ об ответственном подписан, список лиц с доступом составлен
- [ ] В форме галочка согласия пустая, ссылки на документы открываются
- [ ] `LEADS_RETENTION_DAYS` в `.env` равен `retentionDays` в `operator.json`
- [ ] Рабочий чат закрытый, в нём только лица из списка
- [ ] Есть резервная копия `leads.jsonl`, хранится в безопасном месте (и тоже удаляется по сроку)
